# `backend/logic.py`

本文件集中实现比赛编排与赛果计算。函数只处理 JSON 兼容的数据，不访问数据库，也不修改传入对象。后台负责保存阶段数据；本文件负责解析小组规格、创建场次、抽签、排名、淘汰赛晋级。

## 数据约定

- 选手对象：`{"kind":"player|pair|team|undecided|bye","members":["姓名"],"team":"队伍"}`。轮空对象还包含 `"seed":-1`。
- 抽签输入：`{"participant":选手对象,"seed":种子级别}`。小组赛级别为非负整数；淘汰赛正数为种子，`0` 为非种子小组第一，`-1` 为其余选手。`rng_seed` 用于让随机填位和排名抽签在测试中可复现。
- 循环赛及小组赛场次：`a`、`b` 是本组 `participants` 的 **0 起始索引**。
- 小组对象包含 `scheduled_time`（预定时间）、`scheduled_table`（预定桌号）和 `scheduled_referee`（预定裁判），抽签创建时均为空字符串。数据库层在重新抽签时保留已有计划，并同步到新场次。
- 淘汰赛场次：`a`、`b` 是直接可展示的选手对象。
- 每个场次都包含 `id`、`a`、`b`、`finished`、`games`、`table`、`time`、`referee`；淘汰赛场次另外包含从 0 开始的 `round` 和 `index`。`games` 是 `[[A 得分,B 得分], ...]`，每个分数可为非负整数、`"wo"` 或 `null`。普通空分局不参与统计；只填一方 `wo` 的局视另一方为 `0`。桌号和时间初始为 `null`，裁判为空字符串。
- 铜牌赛独立存于淘汰赛阶段的 `bronze_match`，场次 ID 固定为 `bronze`，比分字段与主赛相同。阶段的 `results` 在全部比赛决出前为 `null`；完赛后为最多 8 条 `{rank,participant}`。

## 公共接口

| 函数 | 输入与结果 | 规则 |
| --- | --- | --- |
| `parse_group_spec(expression)` | 如 `"2*4(2) + 1*3(1)"` → `[{"count":2,"size":4,"qualifiers":2},{"count":1,"size":3,"qualifiers":1}]` | 数量、人数均须为正数；每组出线人数须在 1 到小组人数之间。格式错误时抛出 `ValueError`。 |
| `round_robin_matches(participants, *, id_prefix="m")` | 返回单循环场次列表 | 每一对选手恰好交手一次。场次 ID 例如 `m-1`。 |
| `big_score(match)` | 返回 `[A 大比分,B 大比分]`，每项为整数或 `"wo"` | 单方弃权局为对方计一胜局，即使对方只填 `0` 或未填。任一完整局填过 `wo` 的一方，大比分标为 `wo`；双方均填过则为 `wo:wo`。普通不完整局忽略，非弃权完整局分数必须不等。 |
| `match_winner_side(match)` | 返回 `0`（A 胜）、`1`（B 胜）或 `None`（未结束或双方弃权） | 完赛单方弃权时对方胜；双方弃权是合法完赛且无胜者。普通完赛至少有一局完整局，且获胜局数必须有多数。 |
| `rank_round_robin(participants, matches)` | 返回排名顺序的 0 起始选手索引列表，或 `None` | 有任何场次未结束就返回 `None`。依次比较胜场、获胜局、所有完整局的总得分；三项全同者仅按并列选手之间的比赛重算三项，仍并列按展示名排序，名字也相同则保持原次序。 |
| `group_standings(participants, matches, *, rng_seed=None, draw_order=None)` | 完赛后返回 `{order,rows}`，否则 `None` | 先按积分（胜 1，负或双方弃权 0），同分者依次比较彼此间积分、局胜负比、球分胜负比；某一步分出部分名次后，仍同分的子集只用彼此间比赛重新从积分开始比较，仍同分抽签。`rows` 按名次排列，并保留仅涉及比较者的计算过程。 |
| `draw_groups(entrants, group_specs, *, rng_seed=None)` | 返回包含空预定时间、桌号、裁判的小组列表 | 总分组人数必须等于报名人数。非零种子按级别降序排列，前“组数”名依次各进入一个组；额外种子与零级别选手一同重新均匀打乱后填满各组。相同级别随机决定先后；`id` 从 1 开始。 |
| `draw_knockout(entrants, rounds, *, rng_seed=None)` | 返回 `{"drawn":true,"rounds":轮数,"slots":[...],"matches":[...],"bronze_match":...,"results":null}` | 人数须大于签表容量的一半且不超过容量。种子签位按 ITTF 按排名设种规则：一号种子在上半区顶端（下标 0），二号种子在下半区底端（下标 `2**rounds-1`）；3–4 号在上半区底端与下半区顶端之间抽签，5–8 号在奇数四分之一区底端与偶数四分之一区顶端之间抽签，9–16 号对八分之一区同理，直到每场首轮至多一名种子，种子位置上下镜像对称。非种子小组第一随机进入没有种子的首轮场次，上半区占上方签位、下半区占下方签位。轮空每场至多一个，优先放在种子（按号）、再非种子小组第一（按抽签顺序）的同场对面，其余放入随机空场次。其余人按 `group_rank` 从高到低随机填剩余位置；带 `group`、`group_rank` 的条目避开同组已落位者，第二名在另一半区，第三、四名在另外的四分之一区，依此类推，无解时逐级放宽；同级别随机定序。较小签表适用能容纳的批次。主赛共 `2**rounds-1` 场。 |
| `knockout_winner(match)` | 返回已知获胜选手或已确定轮空对象，未决为 `None` | 一方轮空时另一方晋级；双方轮空或已完赛双方弃权时返回轮空，使后续轮次继续传播。普通场次依据已结束的局比分确定胜者。 |
| `refresh_knockout_bracket(stage)` | 返回重新计算后的整个阶段对象 | 从首轮 `slots` 向决赛逐轮计算 `a`、`b`，从半决赛负者推导铜牌赛，并计算 `results`。两边对阵人选未变时保留比分及结束状态；时间、桌号、裁判始终保留。人选改变时清除比分及结束状态。旧 JSON 缺少铜牌字段也可直接读取。 |
| `knockout_champion(stage)` | 返回冠军选手对象，或 `None` | 调用上述更新算法，再读取决赛胜者。 |
| `knockout_results(stage)` | 返回 `[{"rank":1,"participant":...},...]` 或 `None` | 须所有主赛和铜牌赛决出，轮空视为自动决出。冠亚军由决赛定，季殿军由铜牌赛定；四位八强败者并列第五，按选手、组合或团队展示名的字典序排序。参赛人数少于 8 时只列实际选手。 |

`refresh_knockout_bracket` 接收的阶段对象须有正整数 `rounds`、长度为 `2**rounds` 的 `slots` 和场次列表 `matches`。首轮为 `round=0`，决赛为 `round=rounds-1`；每轮的 `index` 从 0 开始。至少 2 轮才有铜牌赛；只有 1 轮时 `bronze_match` 为 `null`。若半决赛有轮空，铜牌归另一场半决赛的败者自动取得。后台录入或修改场次比分后，应再调用该函数并保存返回值，以保证后续轮次和排名自动更新。

## 小组出线后的种子

级别由 `backend/storage.py` 在出线名单确定时计算。`n_s` 为报名中正种子级别人数与小组数的较小值；前 `n_s` 个小组的第一名按组号 `g` 获得 `n_s + 1 - g`，其他组第一为 `0`，其余出线选手为 `-1`。

## 小组排名计算过程

`group_standings` 的每一行包含 `index`、`rank`、`points`、`tied_points`、`game_ratio`、`point_ratio`、`draw_rank`。不需要参与的比较字段为 `null`；比值为 `{won,lost}`，保留整数分子、分母供页面展示，用 Python `Fraction` 精确比较。正数除以零视为正无穷，`0/0` 视为零。用于局数和球分比值的所有 `wo` 都按数值 `0` 计算；比赛积分仍按实际弃权胜负决定，因此 `0:wo` 对手获得 1 积分但该局不增加双方局胜数。

同一总积分的原始并列组，其内部积分、局数比值、球分比值均只取原并列组的相互比赛。每项只进一步区分尚未分开的名次，不在中间重新以更小子集计算。`draw_order` 是全组选手索引的完整排列，由数据库保存，最终仍并列的人按该排列定序；`draw_rank` 是该最终并列子集内从 1 开始的抽签名次。未传排列时可用 `rng_seed` 生成可复现排列。
